# F03/F06 技术方案

新增unified_media_tasks与unified_media_account_holds。父任务保存不变价格、数量、归属与期限，规范化请求/能力及候选快照使用已有SecretEncryptor加密；执行单元状态JSONB逐步持久化。创建事务锁用户和Key，对已用+所有reserved媒体占用检查总额与5h/1d/7d限制，再减可用余额、增frozen_balance。账号预留事务锁父任务与账号行，检查实时quota_used+reserved及日/周窗口。

worker通过FOR UPDATE SKIP LOCKED claim、递增fencing token、30分钟租约接管；每个外部调用前持久提交意图，未知受理只终结释放。已获上游ID只轮询。每URL使用稳定任务/执行单元/结果键转存，并在下载下一URL前保存进度。已完成上游和受理未知的账号消耗保守计量，用户只收S3实际成功交付。

整个任务最多24小时，错误最多5次，按退避调度；健康上游poll不消耗错误次数。最终事务校验claim，原子更新用户冻结/退差、Key用量/窗口与任务completed；重复终结无新增账务效果。资金精度统一decimal8，禁止高于预留capture。GET不解密业务参数、不调用worker。

复用现GRS显式模型定价解析、image/video独立组倍率、用户组倍率、API Key/账号计量函数与S3持久器；用户费用不乘账号倍率。新路径全部组件可用后才挂载。运行验证使用Docker Compose。

账号倍率在提交前按执行单元快照，仅用于共享账号预留/消耗及审计列；用户预留与扣费仅按公开模型、规格及用户组倍率。已创建任务的预留结算允许对应 Key/账号软删除行完成计量，避免撤销凭据使既有资金冻结；新任务与新账号准入仍拒绝软删除。新媒体任务之间以数据库锁保证额度不透支；其它现有文字入口的在途后扣费保持原行为，其跨入口并发硬预留不在本次改动中。
