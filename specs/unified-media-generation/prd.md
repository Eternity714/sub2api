# Sub2API 统一异步生图与生视频接口 PRD

## 1. 文档信息

- **文档名称**：Sub2API 统一异步生图与生视频接口
- **版本**：v1.2-draft
- **日期**：2026-10-15
- **状态**：需求定稿草案，待进入技术方案设计
- **需求范围**：统一 GRS.AI 与 ToAPIs 的图片、视频生成任务接口；接入配置了媒体路由的 Composite 分组；保留其他平台现有媒体入口行为。
- **关联现状**：[MEDIA_API_CURRENT_STATE.md](../../docs/MEDIA_API_CURRENT_STATE.md)
- **模型能力核对**：[capability-matrix.md](capability-matrix.md)
- **P0 特性与依赖**：[feature-breakdown.md](feature-breakdown.md)

## 2. 背景与目标

当前 Sub2API 同时存在 OpenAI/Grok 图片接口、GRS.AI 原生媒体接口、Gemini 批量生图、Grok 视频和其他平台专用接口。不同平台的请求字段、任务状态、结果形态、轮询方式、结果存储和计费时点不一致，下游接入方需要为每个平台或模型编写独立适配。

本项目要为 GRS.AI 与 ToAPIs 建立一套统一的异步图片和视频生成协议。下游只需要提交统一字段并轮询统一任务地址；Sub2API 根据 Composite 分组配置、模型路由和可用账号选择 GRS.AI 或 ToAPIs，负责上游任务提交、状态检查、结果转存、重试、计费和最终结果返回。

目标是降低下游接入成本，同时保留 Sub2API 对上游账号、模型映射、共享账号额度和价格策略的控制权。

## 3. 目标用户与画像

### 3.1 主要用户

- 使用 Sub2API API Key 接入图片或视频生成能力的下游开发者。
- 需要在同一个 API Key 下使用多个媒体模型、而不希望分别对接 GRS.AI 与 ToAPIs 的应用开发者。
- 需要在 GRS.AI 与 ToAPIs 之间配置账号池、优先级和故障切换的 Sub2API 管理员。

### 3.2 反画像

- 只使用 OpenAI、Grok 或其他非媒体 Composite 路由的下游调用方，本期不改变其原有行为。
- 需要直接使用 GRS.AI 或 ToAPIs 原生字段、原生任务 ID、原生回调和原生结果结构的调用方，本期不为其新增统一协议之外的能力。

## 4. 用户故事与场景

- 作为下游开发者，我希望使用同一个图片创建接口和任务查询接口接入 GRS.AI 与 ToAPIs 的图片模型。
- 作为下游开发者，我希望使用同一个视频创建接口和任务查询接口接入 GRS.AI 与 ToAPIs 的视频模型。
- 作为下游开发者，我希望任务创建后立即获得本地任务 ID，而不必保持 HTTP 长连接。
- 作为下游开发者，我希望最终只收到 Sub2API S3 结果 URL，不需要处理不同上游的临时 URL、Base64 或结果结构。
- 作为下游开发者，我希望部分图片生成成功时能拿到成功结果，并知道失败原因，而不必重新发起整项任务。
- 作为管理员，我希望在 Composite 分组中混用 GRS.AI 和 ToAPIs 账号，并控制模型映射、优先级和账号级额度。
- 作为管理员，我希望上游账号的总额、日额、周额由账号管理统一控制，多个用户共用同一账号时共同消耗该额度。

## 5. 功能范围

### 5.1 本期必须实现

1. 新增统一图片创建与查询协议：
   - `POST /v1/images/generations`
   - `GET /v1/images/generations/{task_id}`
2. 新增统一视频创建与查询协议：
   - `POST /v1/videos/generations`
   - `GET /v1/videos/generations/{task_id}`
3. 统一协议只对配置了媒体路由的 Composite 分组生效。
4. Composite 媒体路由支持 GRS.AI 与 ToAPIs 作为目标平台，并允许同一模型配置多个有序候选。
5. 新建独立的 ToAPIs 账号类型；复用现有账号级总额、日额、周额和结算机制。
6. 创建请求强制异步，先返回本地任务，再由服务端持续推进上游任务、转存 S3 和结算。
7. 统一任务状态、响应字段、错误字段和结果字段。
8. 允许图片任务自动拆分为多个上游子任务；整项任务结束后一次性返回最终结果。
9. 部分成功时仅返回成功的 S3 URL，并只对成功结果收费。
10. 创建时预留用户额度；S3 转存完成后正式扣费；最终失败释放冻结额度。
11. 上游提交、上游轮询和 S3 转存具备后台重试与恢复能力。
12. 立即停用以下三个旧 GRS 接口；当前服务确认没有在用调用方：
    - `POST /v1/api/generate`
    - `GET /v1/api/result`
    - `GET /v1/api/tasks`
13. 模型能力规则由管理员维护，支持基础模板复用；调用时必须具有有效的能力 schema，并按请求路径区分图片和视频能力。
14. 首期通过接口文档说明统一字段和各模型支持的参数、限制及调用示例。

### 5.2 本期保留

- 其他平台和其他分组现有的图片、视频、编辑、扩展、批量、对话式媒体入口，继续按当前协议运行。
- GRS.AI 和 ToAPIs 的账号管理、凭证管理、账号测试和管理员额度配置入口。
- 现有素材上传接口，以及未纳入统一协议的批量任务列表、下载、取消等管理接口。

### 5.3 明确不做

- 不为普通 OpenAI、Grok、Gemini 或其他非媒体 Composite 分组强制切换到新协议。
- 不提供客户端 `Idempotency-Key` 语义。
- 不把上游任务 ID、上游账号、上游平台或凭证信息暴露给下游。
- 不让普通用户查看或配置 GRS.AI / ToAPIs 的平台额度或账号额度。
- 不在本期统一编辑、扩展、变体、增强、四宫格后续操作等非“生成”操作。
- Seedream 5.0 Pro 本期支持普通图片生成；图层分解（`layer_decomposition`）后续另议，申请该模式时创建前返回 HTTP 400，不创建任务、不冻结额度。
- 不在本期新增统一回调、列表、取消或事件订阅接口。
- 不在本期提供面向下游的动态模型能力查询接口；以后再评估是否需要，不作为 P1 的交付承诺。

## 6. 详细功能需求

### 6.1 统一图片创建

请求方法和路径：

```text
POST /v1/images/generations
```

请求体统一包含：

```json
{
  "model": "模型标识",
  "prompt": "生成描述",
  "size": "宽高比",
  "n": 1,
  "image_urls": ["https://example.com/reference.png"],
  "metadata": {
    "resolution": "2K",
    "mask_url": "https://example.com/mask.png"
  }
}
```

规则：

- `model` 始终必填；`prompt` 是否必填、可否省略或为空，由该模型及输入模式的能力 schema 决定。文生模式与素材驱动模式分别校验，不为可省略提示词的模式虚构默认提示词。
- `size` 只表示宽高比，不表示像素尺寸。
- 像素规格使用 `metadata.resolution`，支持值以实际模型能力为准，常见值为 `1K`、`2K`、`4K`。
- 图片像素尺寸由 `size` 的宽高比和 `metadata.resolution` 的分辨率档位共同确定，并按具体模型已有依据的规格映射为上游像素值。不同模型同一档位可能对应不同像素，不套用全局换算。本期不新增 `metadata.output_size`；缺少明确映射的组合不开放，不能猜测或降规格。
- `n` 表示期望的图片结果数量；当上游不支持一次生成多个结果时，服务可以自动拆分为多个上游子任务。
- `image_urls` 表示参考图片地址数组；具体角色、蒙版和其他模型特有素材通过 `metadata` 传递。
- 模型特有的其他参数全部放入 `metadata`，由服务根据路由目标和模型能力进行校验与转换。
- 请求校验、模型不存在、路由未配置、媒体能力不匹配、能力 schema 缺失、参数不支持、鉴权失败或权限不足时，直接返回 4xx，不创建任务、不冻结额度、不调用上游。
- 创建前执行第 6.8 节的接口与模型能力校验；通过校验后强制异步处理，返回 HTTP `202 Accepted` 和本地 `task_id`。

### 6.2 统一视频创建

请求方法和路径：

```text
POST /v1/videos/generations
```

请求体统一包含：

```json
{
  "model": "模型标识",
  "prompt": "生成描述",
  "duration": 8,
  "aspect_ratio": "16:9",
  "image_urls": ["https://example.com/start-frame.png"],
  "metadata": {
    "resolution": "1080p"
  }
}
```

规则：

- `model` 始终必填；`prompt` 是否必填、可否省略或为空，由该模型及输入模式的能力 schema 决定。文生模式与素材驱动模式分别校验，不为可省略提示词的模式虚构默认提示词。
- `duration` 表示视频时长，单位和取值范围由统一协议约定，并由目标模型能力校验。
- `aspect_ratio` 表示视频宽高比。
- `image_urls` 表示参考图片或首帧素材；视频、音频、角色等特有输入通过 `metadata` 传递。
- 视频本期不增加顶层 `n` 字段；模型特有的多结果能力通过 `metadata` 传递并按实际能力处理。
- 创建前执行第 6.8 节的接口与模型能力校验；通过校验后强制异步处理，返回 HTTP `202 Accepted` 和本地 `task_id`。

### 6.3 创建响应

创建成功统一返回：

```json
{
  "id": "media_task_01H...",
  "model": "模型标识",
  "status": "queued",
  "progress": 0,
  "created_at": 1792022400
}
```

- `id` 是 Sub2API 本地任务 ID。
- `model` 返回下游提交的公开模型标识。
- 初始 `status` 固定为 `queued`。
- `progress` 按任务状态固定返回整数：`queued=0`、`in_progress=50`、`completed=100`；不返回 `null`，不表达上游实际生成百分比或内部处理阶段。
- `created_at` 为 Unix 秒级时间戳。
- 创建响应不返回上游任务 ID、结果 URL、成功扣费信息或上游错误详情。

### 6.4 任务查询

图片查询：

```text
GET /v1/images/generations/{task_id}
```

视频查询：

```text
GET /v1/videos/generations/{task_id}
```

统一响应字段：

```json
{
  "id": "media_task_01H...",
  "model": "模型标识",
  "status": "completed",
  "progress": 100,
  "created_at": 1792022400,
  "completed_at": 1792022460,
  "expires_at": 1792108860,
  "result": {
    "type": "image",
    "data": [
      "https://s3.example.com/media/media_task_01H.../0.png"
    ]
  },
  "error": ""
}
```

视频任务将 `result.type` 改为 `video`，`data` 仍为字符串数组。

字段规则：

- `status` 只使用：`queued`、`in_progress`、`completed`。
- `queued` 表示已创建并等待执行；`in_progress` 表示任务正在处理，包含上游提交、轮询、结果转存和结算等内部阶段。
- `completed` 只表示整项任务已处理结束，不代表一定成功。
- `progress` 与状态固定对应：`queued` 返回 `0`、`in_progress` 返回 `50`、`completed` 返回 `100`。失败或部分成功的已完成任务同样返回 `100`，成功与否由 `result` 和 `error` 表达。
- 所有终态任务返回 `completed_at`，使用 Unix 秒级时间戳。
- 只有存在至少一个成功结果时才返回 `expires_at`；它表示 S3 结果可获取的截止时间，保留时长由 Sub2API 配置。
- `result` 为对象，包含 `type` 和 `data`。`data` 只包含成功结果的 S3 URL 字符串，不包含 `index`，不包含 Base64，不包含上游临时 URL。
- 失败信息统一放在顶层 `error` 字段，类型为字符串；不使用 `result.errors`。
- 全部成功时 `error` 为空字符串；部分成功时 `data` 只包含成功 URL，`error` 汇总失败原因；全部失败时 `data` 为空数组，`error` 必须有内容。
- 多结果任务必须等待全部子任务进入终态后，统一返回一次最终结果；不得在仍有子任务运行时返回部分终态。
- 任务查询只读取已持久化任务状态，不通过 GET 触发新的生成、换号或重复提交。
- 非本人任务、未知任务 ID 或不属于当前 API Key 的任务，不泄露任务是否存在，统一返回查询错误。

### 6.5 Composite 路由和账号选择

- 统一协议只在 Composite 分组且存在 `images` 或 `videos` 媒体路由时启用。
- Composite 媒体路由按当前分组、请求路径对应的图片或视频能力以及公开模型标识匹配，再选择 GRS.AI、ToAPIs 或两者的有序候选。
- 同一 `public_model` 可以同时登记图片和视频能力；由请求路径选择对应能力及候选，不能仅凭模型名推断或切换到另一种媒体接口。
- 同一 Composite 分组允许同时配置 GRS.AI 与 ToAPIs 账号；具体账号选择由模型路由、账号可用性、账号额度和执行能力共同决定。
- 解除 GRS.AI 作为 Composite 目标平台的排除限制；GRS.AI 仍保持用户平台额度排除，ToAPIs 同样不加入用户平台额度计量。
- 用户侧只能配置自己的 API Key 额度；GRS.AI / ToAPIs 的账号额度由管理员在账号管理中配置，所有使用同一账号的用户共同消耗。
- 任务创建时确认本次参数、能力规则、路由候选和费用依据；具体账号在提交前选择并绑定。没有可用账号不阻止创建本地任务，后续按失败规则结束；已被上游受理的任务继续使用原账号轮询，不切换账号重复生成。
- 上游明确未受理时，允许按候选优先级切换其他可用账号或平台重试；受理状态不明确时先查询原任务，不自动重复提交。
- 没有可用账号、账号额度不足或后台执行失败时，任务仍可进入最终 `completed` 状态并携带 `error`，冻结额度按失败规则释放。

### 6.6 结果转存与计费

- 创建任务时按照 Sub2API 配置的公开模型、输出规格、分辨率、时长和其他定价规则计算预留额度。
- 任务创建后冻结用户侧额度，不在 HTTP `202` 阶段正式扣费。
- 上游结果下载成功且全部需要交付的成功结果已转存到 Sub2API S3 后，按实际成功结果正式扣费。
- 部分成功只对成功结果收费；失败子任务不收费。
- 整项任务最终失败时释放冻结额度，不产生正式扣费。
- S3 转存失败时任务保持 `in_progress`，服务继续重试；达到恢复上限后仍需保留可诊断任务记录，并按最终失败规则释放冻结额度。
- 重试、worker 接管、进程重启和重复查询不能造成重复扣费。
- Midjourney 四宫格作为一个图片结果，按该模型一次生成收费。

### 6.7 旧 GRS 接口关停

- 当前服务确认没有在用调用方；上线时直接停用 `POST /v1/api/generate`、`GET /v1/api/result`、`GET /v1/api/tasks`，不设置迁移期或旧任务排空前置条件。
- 其他平台原有媒体接口不因本项目一起关闭。
- 统一接口任务不复用旧 GRS 查询参数，不接受 `request` 参数。

### 6.8 模型能力配置与创建前校验

- 每个对外开放的生成模型必须具备对应图片或视频能力的有效 schema；可复用基础模板，再针对具体模型补充差异，不能要求每新增一个同协议模型都单独开发接口。
- 模型能力由管理员维护，至少声明媒体类型、适用的公开模型及上游候选、支持字段、必填性、字段类型、可选值、数值范围、默认值及必要的字段组合约束；只声明实际适用的限制。
- `size`、`n`、`duration`、`aspect_ratio`、`image_urls` 和 `metadata` 中模型特有字段的支持情况，以对应能力规则为准；字段放入 `metadata` 不代表可以绕过能力校验。
- 图片路径只匹配图片能力，视频路径只匹配视频能力。视频专用模型提交到图片路径，或图片专用模型提交到视频路径时，立即返回 4xx；不得自动改用另一条生成接口。
- 同名公开模型同时登记图片和视频能力时，两条路径各自使用对应能力进行校验及路由，互不混淆。
- 缺少有效能力 schema 时立即返回 4xx，不允许先创建任务再将全部参数交给上游决定。
- 上述校验必须在任务创建、额度冻结和上游提交之前完成；失败时不产生任务、不冻结用户额度、不调用上游，并返回可定位到模型或字段的错误信息。
- 已创建任务继续遵循创建时确认的能力规则；管理员后续修改能力配置，不得改变在途任务已接受的参数语义和费用依据。
- 顶层字段实行严格白名单：图片接口仅允许 `model`、`prompt`、`size`、`n`、`image_urls`、`metadata`；视频接口仅允许 `model`、`prompt`、`duration`、`aspect_ratio`、`image_urls`、`metadata`。图片接口收到 `duration`、`aspect_ratio`，或视频接口收到 `size`、`n` 等不属于该接口的顶层字段时，返回 HTTP 400，不忽略、不自动迁移到 `metadata`。
- `metadata` 必须为对象，且只允许对应模型能力 schema 声明的字段。未知字段、缺少必填字段、类型不符、枚举或范围非法，以及违反字段组合约束时，返回 HTTP 400，并指出字段路径及原因。
- 请求先按统一接口契约和对应模型能力校验，再筛选完整支持本次全部参数的上游候选；只在这些候选中按配置优先级和账号可用性分发。
- 候选能力判断以完成必要参数转换和允许的任务拆分后，能否满足本次请求语义为准。图片 `n` 表示整项任务期望的结果数；候选原生单次结果数限制不能单独作为排除依据，只要能通过自动拆分满足已配置的统一 `n` 上限，就视为能力匹配。
- 不同候选支持的规格可以不同。某候选不支持本次参数时将其排除；所有候选均不支持时，在创建前返回 HTTP 400，指出不支持的参数或参数组合，不创建任务、不冻结额度、不调用上游。
- 严禁为了切换候选而静默丢弃字段、降低分辨率、调整时长或改变其他已接受的参数；后台重试和故障切换仍必须满足本次全部参数。
- 参数能力全部不匹配属于创建前 400；存在能力匹配的候选但没有可用账号或账号额度不足时，仍按第 6.5 节创建异步任务并最终返回 `completed + error`，释放冻结额度。
- 首期通过接口文档向下游说明统一字段，以及各开放模型的字段类型、必填性、枚举或范围、默认值、字段组合约束和请求示例。文档必须与已启用的能力配置一致，并随模型参数和能力配置变更同步维护；本期不依赖动态能力查询完成接入。

## 7. 非功能需求

- **可靠性**：已返回 `202` 的任务必须具备持久化状态，服务重启或 worker 重启后可以继续处理或进入明确的 `completed + error` 终态。
- **一致性**：任务状态、S3 结果、正式扣费或额度释放必须保持可恢复的一致状态；重复执行不得重复扣费。
- **性能**：正常负载下创建接口 P95 响应时间不超过 500ms；创建接口只等待本地校验、任务持久化和额度预留，不等待上游生成。
- **隔离性**：任务只能由创建任务的用户和 API Key 查询；上游账号、凭证、内部路由和内部错误细节不得泄露。
- **可观测性**：必须能区分任务排队、上游提交、上游轮询、S3 转存、结算和最终失败阶段，并能定位账号、模型和路由候选。
- **存储**：成功生成结果必须先写入 Sub2API 配置的 S3，再向下游返回结果 URL；结果过期时间服从 Sub2API 配置。
- **兼容性**：统一协议只影响配置了媒体路由的 Composite 分组；其他分组既有请求、响应和同步行为保持不变。
- **安全性**：`metadata` 和素材 URL 必须受请求大小、URL 数量、域名访问和敏感字段过滤约束；错误字符串不能包含 API Key、签名凭证或完整上游响应。

## 8. UI 与交互要求

本期不新增下游创作页面。管理端需要能够配置和查看：

- ToAPIs 账号类型及其凭证、启用状态和账号级额度。
- Composite 的图片 / 视频媒体路由、公开模型、上游模型、目标平台、候选优先级和启用状态。
- 图片 / 视频模型能力配置：选择基础模板、配置字段及其限制、区分同名模型的两种能力，并明确提示缺失或无效的 schema。
- 统一媒体任务的阶段、上游平台、结果转存状态、冻结额度、正式费用和错误摘要。

普通用户界面只展示自己的 API Key 额度和任务结果，不展示 GRS.AI / ToAPIs 平台额度或共享账号额度。

## 9. 验收标准

- **AC-001**：Given 一个配置了 `images` 媒体路由的 Composite API Key，When 提交合法图片请求，Then 返回 HTTP 202、唯一本地 `id`、`status=queued`、`progress=0` 和 Unix 秒级 `created_at`。
- **AC-002**：Given 一个配置了 `videos` 媒体路由的 Composite API Key，When 提交合法视频请求，Then 返回 HTTP 202 和统一任务字段；请求不等待上游生成完成。
- **AC-003**：Given Composite 同时配置 GRS.AI 与 ToAPIs 候选，When 模型路由匹配，Then 服务能根据候选顺序和账号可用性选择任一平台，并在任务查询中隐藏上游细节。
- **AC-004**：Given 上游返回 pending 或其他非终态，When 客户端查询任务，Then 任务保持 `queued` 或 `in_progress`，不会被误报为成功。
- **AC-005**：Given 上游生成成功，When 所有成功结果均已转存 S3，Then GET 返回 `completed`、`completed_at`、`expires_at` 和 `result.data` 字符串 URL 数组。
- **AC-006**：Given `n>1` 且服务自动拆分任务，When 部分子任务成功、部分失败且全部子任务均已结束，Then GET 一次性返回 `completed`，`result.data` 只含成功 URL，`error` 汇总失败原因，费用只包含成功结果。
- **AC-007**：Given 所有子任务失败或没有可用上游账号，When 后台处理结束，Then GET 返回 `completed + error`，`result.data=[]`，不返回 `expires_at`，并释放冻结额度。
- **AC-008**：Given 创建时已冻结额度，When S3 转存完成，Then 正式扣费只发生一次；当最终失败时，冻结额度全部释放。
- **AC-009**：Given S3 暂时不可用，When 转存失败，Then 任务保持 `in_progress` 并按配置重试；重试期间不会提前返回完成或重复扣费。
- **AC-010**：Given worker 在上游受理后重启，When 服务恢复，Then 任务继续查询原上游任务，不创建重复生成。
- **AC-011**：Given 查询请求使用其他用户或其他 API Key，When访问已存在的任务 ID，Then 服务不泄露任务存在性并返回查询错误。
- **AC-012**：Given 非 Composite 分组或未配置媒体路由的 Composite 分组，When 调用统一路径，Then服务按既有平台行为返回不支持或继续走原有接口，不误进入统一任务链路。
- **AC-013**：Given 当前旧 GRS 接口没有在用调用方，When 发布关停版本，Then `/v1/api/generate`、`/v1/api/result`、`/v1/api/tasks` 立即停用，无需迁移期或旧任务排空；其他平台媒体接口仍可用。
- **AC-014**：Given 请求包含模型特有参数，When 参数位于 `metadata`，Then 服务按目标模型能力校验并转换；本地已能判定不支持的参数在创建前返回 4xx，上游执行期间新增的拒绝或错误写入最终 `error`，不能静默丢弃参数。
- **AC-015**：Given 模型只配置视频能力，When 使用图片生成路径提交该模型，Then 返回 4xx，不创建任务、不冻结额度、不调用上游；图片专用模型提交到视频路径时同理。
- **AC-016**：Given 同一 `public_model` 已分别登记图片和视频能力，When 分别调用两条生成路径，Then 各自匹配对应能力并进行参数校验，不因同名而报歧义或选错媒体类型。
- **AC-017**：Given 模型路由存在但没有有效能力 schema，When 提交生成请求，Then 返回 4xx，并说明能力配置不可用，不创建任务、不冻结额度、不调用上游。
- **AC-018**：Given 管理员复用基础模板配置一个现有适配协议支持的新模型及其差异字段，When 保存有效能力配置并启用相应路由，Then 可以按对应媒体接口调用该模型，无需为该模型新增独立接口。
- **AC-019**：Given 调用图片接口时在顶层传入 `duration` 或 `aspect_ratio`，或调用视频接口时在顶层传入 `size` 或 `n`，When 执行创建前校验，Then 返回 HTTP 400 并指出字段，不创建任务、不冻结额度、不调用上游；其他未知顶层字段同理。
- **AC-020**：Given 请求包含 schema 未声明的 `metadata` 字段，或声明字段的类型、枚举、范围、必填性或组合约束不合法，When 执行创建前校验，Then 返回 HTTP 400 并指出字段路径及原因，不创建任务、不冻结额度、不调用上游。
- **AC-021**：Given 同一公开模型的候选 A 只支持 2K、候选 B 支持 4K，When 提交有效的 `metadata.resolution=4K` 请求，Then 仅候选 B 可以被选择；候选 B 没有可用账号时不得降级到候选 A，任务按无可用账号规则最终失败并释放冻结额度。
- **AC-022**：Given 所有路由候选均不支持请求的某参数或参数组合，When 执行创建前校验，Then 返回 HTTP 400 并指出原因，不创建任务、不冻结额度、不调用上游，不静默修改参数。
- **AC-023**：Given 唯一候选单次只能生成 1 个图片结果，但统一模型能力允许 `n=3` 且其余参数均受支持，When 提交 `n=3` 的图片请求，Then 返回 HTTP 202 并自动拆分为 3 个上游子任务，不因候选原生单次数量限制返回 400。
- **AC-024**：Given 已创建的统一媒体任务，When 状态依次为 `queued`、`in_progress`、`completed`，Then `progress` 分别固定为 `0`、`50`、`100`；全成功、部分成功和全失败的已完成任务均返回 `100`，并通过 `result`、`error` 区分结果。
- **AC-025**：Given 一个已开放的图片或视频生成模型，When 下游开发者查阅首期接口文档，Then 能查到统一字段及该模型支持参数的类型、必填性、枚举或范围、默认值、组合约束和请求示例，且与已启用的能力配置一致，无需动态能力查询即可构造合法请求。

- **AC-026**：Given 某模型的输入模式明确允许省略 `prompt`，When 请求提供该模式要求的有效素材和其它参数，Then 不因全局提示词必填规则拒绝；对于 schema 要求 `prompt` 的模式，缺失时创建前返回 HTTP 400，不创建任务、不冻结额度。
- **AC-027**：Given Seedream 5.0 Pro 的普通生成能力已配置，When 请求普通生图，Then 按统一图片协议处理；When 请求图层分解模式，Then 创建前返回 HTTP 400，不创建任务、不冻结额度，不返回被截断的图层结构结果。

## 11. 度量指标

- 统一接口的合法创建请求中，HTTP 202 返回成功率达到 99.9%。
- 已受理任务中，任务状态、结果和费用最终一致率达到 99.99%。
- 任何任务在重试、重启或多 worker 接管下的重复正式扣费率为 0。
- 结果转存暂时失败时，任务在恢复窗口内被重试处理的比例达到 99.9%。
- 统一接口覆盖的 GRS.AI 与 ToAPIs 已配置生成模型达到 100%；不支持的模型必须在路由或请求校验阶段明确暴露原因。
- 下游接入图片或视频生成时，只需实现四个统一接口，不需要按 GRS.AI 与 ToAPIs 编写平台专用协议适配。

## 12. 依赖与约束

- GRS.AI 和 ToAPIs 的可用模型、参数和任务状态以已配置账号及实时上游能力为准；Sub2API 模型路由是对外可用模型的控制来源。
- ToAPIs 文档来源为 <https://docs.toapis.com/docs/cn/api-reference/models>；具体模型特有操作需按模型逐项确认。
- 结果 S3、任务持久化、后台 worker、账号凭证、Composite 路由、账号级额度和现有结算能力必须可用。
- 用户平台额度继续保留 GRS.AI 排除，且 ToAPIs 本期不加入；这与 Composite 是否允许目标平台无关。
- 上游账号额度属于账号管理功能，多个用户使用同一账号时共享；普通用户无法查看或修改。
- 本机测试必须通过 Docker Compose 测试容器执行。
- 模型能力配置保存于数据库，由管理员通过管理后台维护，代码提供可复用的基础模板；具体存储结构和适配实现由技术方案确定。
- 本期不授权生产部署；未来上线遵守项目灰度发布规则，旧 GRS 三个接口直接停用，无需等待旧任务排空。

## 13. 风险与开放问题

### 13.1 已识别风险

- 同一公开模型可能同时存在于 GRS.AI 与 ToAPIs，但参数名、状态语义、结果数量和分辨率能力不同，若能力校验不足会出现“请求已接受但参数未生效”。
- 上游提交成功但网络断开时，若无法确认受理状态，重复提交可能造成重复生成和账务争议。
- S3 转存与扣费分属不同外部资源，必须保证任务终态不会早于结果交付或账务决议。
- 模型能力配置可能随上游变化而过时；需明确维护责任，并区分本地校验失败和上游执行失败，避免错误宣称参数已生效。
- 上游账号额度是共享资源，多用户并发创建可能在预留与实际扣费之间形成暂时额度压力。

### 13.2 待分阶段收敛的事项

这些事项不整体阻塞技术方案。影响首期范围、对外协议或收费规则的新增选择，需要用户定稿；工程限制与配置默认值在对应技术方案中提出并说明依据。

| 事项 | 处理方式与阶段 |
| --- | --- |
| `metadata` 最大大小、嵌套深度和保留字段 | 技术方案中确定工程限制，并同步到接口文档与校验规则；涉及改变已确认字段语义时再提问。 |
| 生成所需的图像、视频、音频、角色参考等特殊输入 | 先按覆盖两平台生成模型的既定范围整理能力清单；能由统一字段和 `metadata` 表达的输入纳入逐模型 schema。无法表达或涉及范围取舍的具体能力单独提请用户定稿。延长、变体等非生成操作仍不在本期。 |
| S3 结果保留时长 | 保留管理员配置原则；技术方案评估现有设置能否复用，提出默认值与上限建议。需要新增或改变既有保留策略时再提请确认。 |

### 13.3 已确认的协议与能力配置决策

- `model` 始终必填；`prompt` 是否必填由模型和输入模式 schema 决定。
- 图片维持 `size` 宽高比 + `metadata.resolution` 分辨率档位，由模型规格映射上游像素；本期不新增 `metadata.output_size`。
- Seedream 5.0 Pro 保留普通生成，图层分解模式本期返回 400，后续另议。

- 首期通过接口文档说明统一字段和逐模型参数；动态能力查询以后再评估是否需要，不纳入本期或 P1 的交付承诺。
- `progress` 按状态固定为 `queued=0`、`in_progress=50`、`completed=100`；`100` 表示处理结束，不能据此判断成功。
- 模型能力由数据库配置和管理后台维护，代码提供基础模板。
- 未配置有效能力 schema 的调用返回 4xx，不创建任务。
- 同一 `public_model` 可同时登记图片和视频能力，由请求路径选择。
- 严格校验对应接口的顶层字段与模型 schema 声明的 `metadata` 字段；不合法时返回 400，不创建任务、不冻结额度。
- 只在完整支持本次全部参数的候选中分发；全部候选不支持时返回 400，禁止静默降级或丢弃参数。

## 14. 里程碑

1. **需求与能力基线**：同步已确认的 PRD，核对两平台生成模型和参数，识别确实影响范围与协议的未决项。
2. **P0 特性拆分**：按依赖拆出接口与能力校验、账号与路由、持久任务、上游适配、S3 交付、结算和切换验收等特性，建立需求与验收标准的归属。
3. **逐特性规格与技术方案**：依次执行 Spec-Kit `specify → plan`；`plan` 阶段承载技术方案，共用任务、路由、存储和结算约定由后续特性引用。
4. **任务与实现验证**：对应方案收敛后执行 `tasks → implement`，逐特性完成接口契约、权限、额度、重试、恢复、账务和 Docker Compose 集成验证。
5. **上线准备**：候选版本验证、灰度流量切换和旧 GRS 三个接口直接关停。

下一步先交付模型能力对照表和 P0 特性拆分。随后按特性执行 `specify → plan → tasks → implement`；第 13.2 节按所属阶段收敛，只有影响本期范围、对外协议和收费规则的未决事项才阻塞相关部分，不要求先定死所有工程参数。
