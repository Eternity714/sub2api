# 同域文档中心需求

## 文档信息

日期：2026-10-09。状态：本地回归通过，生产灰度验收待完成。范围：单一文档中心功能、支持主题迁移及已授权的提交推送与生产灰度发布。

## 背景与目标

用户需要从站点进入使用文档，并参考 https://docs.fastaitoken.com/docs/ 的内容组织与阅读体验。用户确认同时建设入口和文档内容，随后明确地址为 https://www.gkotta.bid/docs，不新增 DNS。

## 目标用户与场景

首次接入的用户需要完成开户、创建密钥和首次请求；已有用户需要查阅 Claude Code、Codex、通用客户端配置、接口和常见故障。访客无需登录即可阅读。

## 功能与范围

必须提供首页及控制台入口、文档首页、分类导航、全文检索、文章目录、代码复制、亮暗主题和移动端阅读。内容覆盖入门、密钥、客户端、API、计费及排错。

用户明确只迁移 Gkotta 已支持的功能。逐项盘点参考站 49 个入口，覆盖兼容的聊天、编程、Agent、翻译与工作流客户端，以及现有图片、Grok 视频、Seedance 和图转视频 API。重复入口合并为完整教程，过期配置以当前官方文档修正，专属产品和未经验证的适配排除并记录原因。

用户后续明确授权提交推送、生产灰度发布和晋升，发布按项目既有灰度流程执行。本次交付不包括 DNS 配置、在线文档编辑、社区客服承诺、参考站专属优惠或未经本项目证实的接口。

## 详细行为与边界

文档文章有独立可分享的地址。无匹配文章时显示文档内的未找到提示和返回入口；搜索无结果时说明结果为空。文章中的配置使用占位密钥，不读取或展示账户密钥。已有批量生图文档地址继续提供原有登录保护。

## 非功能要求

静态内容不依赖新的服务或第三方文档站。文档工具统一构建 Markdown，不能每页手写 HTML。保留站点严格 CSP，通过服务端 nonce 允许文档工具必需脚本。移动端无整体横向溢出，长代码块在自身区域滚动。首版文档界面及教程正文为简体中文。

## 交互方向

参考站为 VitePress 文档站。用户明确要求复用现有工具，不要每页单独写 HTML。文档首页使用工具提供的快速卡片；文章借鉴顶部品牌/搜索/主题入口、左侧分类目录、中央正文及右侧页内目录。正文按本项目真实入口和接口重写。

## 验收标准

- AC-001：从默认首页、紧凑首页、控制台或密钥用量页点击文档，进入本站 `/docs`；移动端侧栏也可进入。
- AC-002：访客直接访问 `/docs` 或有效文章地址可以阅读，在后端模式也可阅读；`/docs/batch-image` 保留鉴权，不扩大其它路径的公开访问权限。
- AC-003：导航、首页快捷入口、上/下一篇可进入相应文章；未知文章有明确提示且不会伪装成入门文章。
- AC-004：按标题或正文关键词能找到对应文章；空查询不显示结果，找不到时显示空结果提示。
- AC-005：正文标题生成目录锚点，代码可复制；文档 HTML 中脚本 nonce 与响应 CSP 匹配。
- AC-006：文档可在窄屏阅读并展开目录，主题切换持久化，界面和教程统一中文。
- AC-007：参考站全部 49 个入口在覆盖表中有迁移、合并、部分适配或排除结论；迁移教程给出对应 Gkotta 地址、分组条件、配置和验证，不能把参考站专属界面写成本站功能。
- AC-008：部署可从主机挂载已生成的文档目录；更新完整静态文档后刷新即可读取，目录为空时保留内置文档，两个灰度槽位的文档互不覆盖。

## 优先级与度量

以上均为本次 MVP。完成指标为全部验收场景通过、关联前端回归通过、构建成功及独立审查无阻塞问题。

## 依赖、风险与开放问题

接口和模型可用性以站点实际授权分组为准；教程不承诺固定模型、价格或 SLA。生产可访问性及双槽文档隔离需要在候选槽位验收，再按既有流程扩大流量并晋升；实际发布结果记录在验证文档中，不预先宣称上线。目前无阻塞实现的产品问题。

## 里程碑

需求与参考调研 → 实现文档中心 → 容器检查、构建与评审 → 提交推送 → 无流量候选槽位验收 → 逐步放量、观察及晋升 → 核对生产状态。
