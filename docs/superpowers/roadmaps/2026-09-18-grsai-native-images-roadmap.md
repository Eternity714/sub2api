# grsai 原生生图接入 Roadmap

**日期：** 2026-09-18
**关联规格：** [grsai 原生生图接入设计](../specs/2026-09-18-grsai-native-images-design.md)
**状态：** 候选后续阶段，尚未批准实施

本 Roadmap 收集已经识别、但不属于“原生 `/v1/api/generate` 接入与可靠结算”第一阶段的工作。各阶段均需在开始前单独完成设计、评审和批准；条目顺序表示建议依赖关系，不构成实施承诺。

## 第一阶段后：模型参数档案

为 grsai 模型建立可配置的能力档案，并在请求进入上游前进行差异化处理：

- 按模型定义支持的参数、枚举值、数值范围、图片数量与尺寸限制。
- 定义参数默认值、冲突字段优先级和可见的本地参数错误。
- 对参数不支持时选择拒绝、移除或显式降级，而不是仅依赖上游静默替换。
- 在管理端提供模型能力和参数规则的维护入口。

前置条件：积累各模型的官方参数契约与真实响应样本，并确认“本地拦截”不会破坏当前允许上游静默替换的兼容策略。

## 后续阶段：任务查询与异步能力

在第一阶段内部查询和结算恢复稳定后，评估向用户公开任务生命周期能力：

- `GET /v1/api/result` 的用户可见版本，需采用 API Key 与用户双重归属校验，避免任务枚举和跨 Key 读取。
- 公开异步提交与轮询的响应契约、超时、结果保留时间和任务取消语义。
- 若开放流式或进度推送，定义断线恢复、事件序号与结算完成时机。
- 将 `running` 任务的内部查询、失败重试与用户可见状态统一为同一状态机。

前置条件：完成任务数据保留、鉴权、限流、并发、监控和成本评估；公开接口不得暴露上游 Key、内部账号 ID 或运营诊断信息。

## 流式与异步生成模式

第一阶段的原生接口仅接受同步 `replyType=json`。下列两种模式在后续单独设计和实现：

- **`async` 模式：** 定义异步提交响应、用户任务 ID、轮询或回调方式、结果保留与取消语义。提交阶段不扣费；仅在内部确认上游任务最终 `succeeded` 后进入同一套幂等结算流程。
- **`stream` 模式：** 定义进度或结果事件格式、事件序号、断线恢复、代理超时和客户端取消语义。流式事件不能改变“仅成功结算一次”的规则，也不能在事件中泄露上游账号与密钥信息。

两种模式均要求先明确 grsai 上游对异步/流式的实际支持和计费行为，并覆盖重复提交、客户端断开、服务重启、上游任务失败与结算重试的端到端测试。完成前，原生接口继续在本地拒绝 `async=true` 和 `stream=true`。

## 兼容层评估：OpenAI 图片接口

评估是否通过 `/v1/images/generations` 和 `/v1/images/edits` 为 grsai 提供 OpenAI 兼容入口：

- 需要明确 OpenAI 标准字段与 grsai 原生字段的映射、冲突规则和不可映射字段的错误行为。
- 保持原生 `/v1/api/generate` 作为完整能力接口；兼容层不能改变原生协议语义。
- 评估 OpenAI SDK 兼容性、响应映射的可观察性，以及调用者无法表达原生参数时的降级风险。

该项当前没有实施决定。第一阶段维持接口分离，既有 OpenAI 生图接口不接入 grsai。

## Composite 分组支持

为 `POST /v1/api/generate` 增加 composite 分组路由能力，使同一用户 API Key 可以按请求中的 `model` 被解析到 grsai 目标平台和对应渠道。

- 扩展 composite 路由端点类型，使原生生图请求可以用模型名解析目标平台、上游模型名与渠道映射。
- 仅当解析结果为 `platform=grsai` 时进入 grsai 原生处理器；解析到其他平台或无匹配模型时返回明确的本地路由错误，不得尝试跨平台转发。
- 账号选择、模型价格快照、上游任务 ID 和结算记录必须绑定解析后的 grsai 目标分组、渠道与账号，而不是 composite 外层分组的默认平台。
- 为模型白名单、请求体改写、并发限制、运营指标和失败恢复补充 composite 场景测试。

前置条件：第一阶段的直接 `platform=grsai` 分组已稳定运行，且 composite 路由器能够为 `/v1/api/generate` 安全解析 `model` 字段。该项完成前，composite 分组访问原生 grsai 接口仍保持拒绝。

## 运营与配置演进

- 自动发现或同步 grsai 模型、能力和官方价格，并提供人工审核与回滚。
- 价格自动换算、成本监控、模型级毛利阈值和异常扣费对账视图。
- 专用运营界面：结算重试、`manual_review` 队列、上游任务核查和审计导出。
- 可选的存量 OpenAI 账号/分组/渠道迁移助手；迁移必须是显式、可预览、可回滚的管理操作，默认不迁移任何配置。

前置条件：第一阶段的 grsai 平台、价格快照和结算记录已在生产观察期内稳定运行。

## 上游可靠性增强

- 如果 grsai 后续支持客户端生成幂等键或按客户端请求 ID 查询任务，接入该能力以缩小“上游已接收但本地未持久化任务 ID”的不确定窗口。
- 在此之前，未知任务 ID 始终转 `manual_review`，不得自动重发生成请求。

## 进入下一阶段的门槛

每一项进入实施前至少满足以下条件：

1. 第一阶段的核心成功、失败、`running`、重试与恢复用例持续通过。
2. 结算记录没有未处理的异常积压，`manual_review` 有明确的运营处理责任人和流程。
3. 上游协议、模型参数或接口行为已经通过文档和实际请求验证。
4. 新阶段完成独立设计审批，且不会改变已发布的原生接口和既有 OpenAI 路由的承诺。
