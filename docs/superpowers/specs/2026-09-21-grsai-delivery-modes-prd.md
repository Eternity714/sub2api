## 2. 背景与目标

第一阶段已经具备 GRS.AI 原生生成、任务恢复和成功后结算能力，但调用方不能选择
同步聚合、实时流或异步交付，也不能安全查询自己的任务状态。

本 feature 的目标是：下游调用方用一个明确字段选择交付方式；只有创建该任务的用户和 API Key
可以查询结果；无论交付方式如何，成功任务最多收费一次，失败任务不收费。

非目标：OpenAI 图片接口兼容、Composite 分组、模型参数档案、用户取消任务、上游原生 async、
上游非流式协议。

## 3. 目标用户与反画像

| 类型 | 定义 |
| --- | --- |
| 目标用户 | 使用 GRS.AI 原生接口、希望获得最终 JSON、进度流或异步任务结果的 API Key 调用方 |
| 运营用户 | 需要核对异常任务、冻结额度和结算结果的管理员 |
| 反画像 | 试图用其他用户的任务 ID、其他 API Key 或猜测 ID 读取任务的调用方 |

## 4. 使用场景

1. 调用方未指定交付方式，等待并获取最终生成结果。
2. 调用方请求实时进度流，并在断线后通过任务查询继续查看结果。
3. 调用方提交耗时任务，立即取得本地任务 ID，稍后主动查询状态与结果。
4. 管理员处理没有安全关联到上游任务 ID 的异常任务；系统不得重发生成请求。

## 5. 功能范围

### In Scope

- 通过 `replyType` 选择 `json`、`stream` 或 `async`；缺省为 `json`。
- 提供 `GET /v1/api/result?id=...` 的用户可见任务查询。
- 支持同一用户和同一 API Key 的双重任务归属校验。
- 支持同步、流式和异步任务的统一状态、结果、结算和异常恢复体验。
- 提交时冻结额度，最终成功时结算一次；失败、违规和未知结果不收费。
- 提供显式运行的 GRS.AI 真实协议探测。

### Out of Scope

- 不支持 `stream=true` 或 `async=true`。
- 不提供任务取消接口。
- 不向上游发送 `replyType=json` 或 `replyType=async`。
- 不承诺上游 credits 的退款规则等同于 Sub2API 的计费规则。

## 6. 详细功能需求

### F1. 交付方式选择

| 项目 | 需求 |
| --- | --- |
| 触发 | 调用方提交 `POST /v1/api/generate` |
| 输入 | `replyType` 为 `json`、`stream` 或 `async`；未传时为 `json` |
| 输出 | JSON 返回最终结果；Stream 返回进度事件；Async 返回已接受的本地任务标识 |
| 边界 | 其他值或非字符串返回本地 400；不接受布尔替代字段 |

### F2. 任务查询

| 项目 | 需求 |
| --- | --- |
| 触发 | 调用方发起 `GET /v1/api/result?id=...` |
| 输入 | 自己的本地任务 ID 或已关联的上游任务 ID |
| 输出 | 安全任务视图，含状态、进度、模型、时间、结果和有限错误摘要 |
| 边界 | 非归属任务、未知任务和无效 ID 均返回 404；不得泄露账号、内部价格、凭据或诊断详情 |

### F3. 异步交付

| 项目 | 需求 |
| --- | --- |
| 触发 | `replyType=async` |
| 输入 | 合法 GRS.AI 生成请求 |
| 输出 | 202 及可查询的本地任务 ID |
| 边界 | 提交被接受不代表已生成成功；任务不支持用户取消；服务重启后任务仍可继续处理或进入人工核查 |

同一用户（跨其所有 API Key）的 Async 任务，等待中最多 20 个、进行中最多 3 个。等待名额在受理时核验；满额时返回 429，且不得创建任务或冻结额度。进行中名额在后台领取时核验；满额任务保留等待状态，不向上游提交。进程重启、任务租约过期及多实例并行不能绕过上限；任务到达成功、失败或人工核查等终态后释放进行中名额。JSON 和 Stream 不计入这两个 Async 上限。

### F4. 流式交付

| 项目 | 需求 |
| --- | --- |
| 触发 | `replyType=stream` |
| 输入 | 合法 GRS.AI 生成请求 |
| 输出 | 实时、顺序一致的任务进度和终态事件 |
| 边界 | 客户端断线不取消任务；已识别任务仍可经查询获得终态；未安全识别任务不得自动重发 |

### F5. 计费与冻结

| 项目 | 需求 |
| --- | --- |
| 触发 | 任务被接受、完成或关闭 |
| 输入 | 任务创建时可确定的模型、图片数量、规格和适用价格 |
| 输出 | 可用额度被冻结、成功后一次结算，或在不收费终态释放冻结 |
| 边界 | 失败、违规、未知提交和结算未完成均不得重复扣费 |

### F6. 真实契约探测

| 项目 | 需求 |
| --- | --- |
| 触发 | 维护人员显式运行 live probe |
| 输入 | 受环境变量保护的凭据、`nano-banana-2-lite` |
| 输出 | 脱敏的流帧与任务查询摘要 |
| 边界 | 默认不发起网络调用、不进入 CI、不输出密钥、完整提示词、图片 URL 或原始响应 |

## 7. 非功能需求

- 任务查询的归属判断不得允许跨 API Key 或跨用户读取。
- 客户端断线、进程重启和 Worker 重试不得生成第二个上游任务或重复结算。
- 原始请求只在完成任务所需的有限期间保存；终态后按保留策略清除。
- JSON 和 Stream 交付的首个可见响应应保持各自稳定的响应类型；错误格式可预测。
- 协议探测必须显式启用，且单次只允许创建一个真实生成任务。

## 8. UI 与交互

本 feature 面向 API，不新增用户界面。管理员继续通过现有运行和审计能力处置异常记录。

## 9. 验收标准

1. **AC-001** Given `replyType` 缺失，When 提交合法请求，Then 调用方收到最终 JSON 或标准错误。
2. **AC-002** Given `replyType=stream`，When 任务运行，Then 调用方收到有序进度和一个终态事件。
3. **AC-003** Given `replyType=async`，When 提交合法请求，Then 服务返回 202 和可查询任务 ID，且不等待生成完成。
4. **AC-004** Given 任务属于 API Key A，When API Key B 或其他用户查询它，Then 返回 404。
5. **AC-005** Given 最终状态为 `succeeded`，When 发生并发恢复或重试，Then 最多产生一次结算。
6. **AC-006** Given 最终状态为失败、违规或未知提交，Then 不产生结算并释放冻结额度（若已建立）。
7. **AC-007** Given 客户端在已识别任务后断线，When 后台恢复完成，Then 任务可查询且按最终状态处理。
8. **AC-008** Given 未显式开启 live probe，When 常规测试或 CI 执行，Then 不访问 GRS.AI。
9. **AC-009** Given 同一用户已有 20 个等待中 Async 任务，When 用该用户任一 API Key 再提交，Then 返回 429，且不新增任务、不冻结额度。
10. **AC-010** Given 同一用户已有 3 个进行中 Async 任务，When 后台尝试领取其等待任务，Then 该任务仍等待且不产生新的上游提交；任一进行中任务终结后才可领取。
11. **AC-011** Given 多实例同时受理或领取、或进行中任务租约过期并重启，When 统计同一用户的任务，Then 等待和进行中任务分别不超过 20 和 3。

## 10. 优先级与 MVP

| 优先级 | 范围 |
| --- | --- |
| P0 | 统一 `replyType`、上游统一 Stream、任务查询、归属校验、冻结与一次结算 |
| P0 | JSON 与 Async 交付、异常恢复、真实协议探测 |
| P1 | Stream 对外开放及断线恢复，须通过真实契约门槛 |
| P2 | 后续模型能力档案、Composite、OpenAI 兼容层 |

## 11. 度量指标

- 任务查询越权成功次数为 0。
- 已结算任务的重复扣费次数为 0。
- `manual_review` 数量和冻结额度滞留数量均可观测。
- Stream 断线后可恢复查询的任务比例可观测。

## 12. 依赖与约束

- 依赖 GRS.AI 当前可用的流式原生生成和任务结果查询能力。
- 真实探测使用 `nano-banana-2-lite`，每次运行最多提交一个生成任务；上游费用不作为本次功能验收门槛。
- 现有公开同步 JSON 语义不得被破坏。

## 13. 风险与开放问题

| 风险或问题 | 处置 |
| --- | --- |
| 上游流协议变化 | 以显式 live probe 更新基线；未通过则不开放 Stream |
| 上游已接收但未返回任务 ID | 转人工核查，不自动重发 |
| 上游 credits 退款规则变化 | 不纳入本次探测；本地结算仍以最终任务状态为准 |
| 任务与原始请求保留期限 | 初始采用终态安全视图 24 小时；上线前由运营确认配置化期限 |
| Async 每用户容量 | 等待中 20、进行中 3；跨 API Key 共享，超出受理上限返回 429 |

### 已否决方案

| 方案 | 不采用原因 |
| --- | --- |
| 预扣费后失败退款 | 上游失败和退款规则存在差异，容易产生重复退款或账务争议 |
| 按下游方式直连上游 JSON/Async | 已确认上游统一采用 Stream，避免三套不一致的任务状态机 |
| 用户取消任务 | 尚未验证上游取消语义，本地取消无法保证阻止已提交任务 |
