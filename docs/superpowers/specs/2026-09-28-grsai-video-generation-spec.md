## 现状与目标

2026-09-27 在生产稳定槽位验证：GRS.AI 分组、账号映射和渠道中的
`minimax-h3` 视频定价均已配置。渠道价格为 480p $0.10/秒、768p $0.14/秒、
1080p $0.30/秒。使用有效 API Key 提交 480p、1 秒、`replyType=async` 请求，
网关返回 HTTP 400 `GRS.AI request or pricing is invalid`；账号已选中，但未创建
任务或用量记录。当前 GRS.AI 定价入口仅接受 `image`/`per_request`，且拒绝
分辨率阶梯价；后续结果解析、转存和任务用量仍按图片处理。

目标是在既有 `POST /v1/api/generate` 上完成视频任务的生成、查询、存储与
计费闭环。沿用现有 API Key、分组、账号、渠道、余额、持久任务、三种交付方式
和对象存储能力；现有图片请求及历史任务保持原有行为。

## 需求契约

1. **入口与权限。** 视频仍使用 `POST /v1/api/generate`。API Key 所在分组的
   模型许可、账号选择、并发、安全审核和现有 `allow_image_generation` 开关继续
   生效。后台开关显示为“允许图片/视频生成”，字段名及既有配置值不变。
2. **路径判定。** 按现有优先级解析该分组及其渠道的模型定价；命中
   `billing_mode=video` 时按视频任务处理。无需模型名称分类表或新增请求类型
   字段。没有可用视频价格的请求在触达上游之前返回明确错误。
3. **请求。** `replyType=json|stream|async` 的含义及缺省行为与现有图片任务
   一致。视频计费需要有效的整数秒 `duration`；若价格按分辨率分档，请求必须
   提供能命中配置档位的 `resolution`。`minimax-h3` 遵守其上游文档：
   480p/768p/1080p、1-15 秒，1080p 最多 10 秒。`prompt`、`aspectRatio`、
   `images`、`audios`、`seed` 及未来模型新增的非控制参数保留并透传上游；
   网关仅为鉴权、既有安全审核、计费和交付读取必要字段。未来模型若使用新的结果结构或计费
   单位，则需另行适配。
4. **价格与余额。** 按 API Key 所在分组解析模型渠道价格。每个视频 URL
   单独按命中模型及分辨率的每秒价格 × 请求 `duration`，再按现有用户/分组
   有效倍率或视频独立倍率及账号倍率计算实付；最终金额为各视频 URL 的
   费用之和。例如返回 3 个 URL，即收 3 份单视频费用。分辨率档位存在时
   须精确命中，不以默认价代替缺失档位；没有档位而配置平价时，平价按
   每秒价使用。提交前保存价格、分辨率、时长和倍率快照，并至少冻结
   一份单视频费用；结果到达后以实际视频 URL 数计算最终金额。若最终
   金额超过预冻结金额，须在公开成功前完成差额扣取和幂等结算，余额
   不足时如何处理仍待确认。后续改价不影响已创建任务。
5. **交付与结果。** 沿用现有本地任务 ID、JSON/Stream/Async 响应和同一 API Key
   的结果查询/列表权限。上游 `results[]` 可以返回多个 URL；按本次请求
   解析出的媒体类型逐项转存到已配置的 S3，
   图片沿用现有多图处理，视频的每个 URL 分别转存为 MP4。下游 `results[].url`
   按上游顺序指向本地可访问对象，不暴露上游任务 ID 或原始链接。任一结果
   下载、验证或转存失败时，任务不得公开部分成功；只有全部对象转存、结果
   入库和幂等结算完成后才公开 `succeeded`。链接期限沿用现有公开 URL 或
   presigned URL 契约。
6. **失败与恢复。** 上游明确失败/违规时释放冻结且不收费；提交结果不确定且
   没有上游 ID 时不自动重发。已绑定上游 ID 的任务在重启后只查询结果。
   下载、上传或数据库保存失败时不报告成功，按现有有界重试和人工核查规则
   处理。重复轮询、并发 worker 和客户端断线均不得重复生成或扣费。
7. **灰度共库。** 新视频任务不得被只认识图片结果的旧 worker 领取；新版本
   必须继续处理旧图片任务。0% 候选验证及回滚期间，任务、冻结余额和结算
   状态不得丢失或被错误处理。

## 验收标准

| ID | Given / When / Then |
| --- | --- |
| GRSAI-VIDEO-01 | 给定已配置的分组、渠道价格和账号映射，提交 `minimax-h3` 视频请求时，网关接受现有 API Key 和权限开关，不要求额外模型分类配置。 |
| GRSAI-VIDEO-02 | 给定 480p/768p/1080p 各自的渠道档位，提交合法时长时按对应每秒价格、请求时长和现有视频倍率预冻结一份费用；结果有 N 个视频 URL 时，最终金额为 N 份单视频费用，差额和 API Key quota、用量与最终金额一致。缺少时长或所需档位时在上游 POST 前拒绝且不冻结。 |
| GRSAI-VIDEO-03 | 给定模型附带参考图、音频、种子或额外非控制字段，提交时这些参数到达上游，交付方式控制字段仍按本地三模式契约处理。 |
| GRSAI-VIDEO-04 | 给定 JSON、Stream、Async 任一交付方式及多个结果 URL，响应只使用本地任务 ID 和安全状态；所有图片或 MP4 按原顺序转存、结果入库并完成结算后才公开最终成功及对应的本地链接。 |
| GRSAI-VIDEO-05 | 给定上游失败、任一结果转存失败、差额结算失败、数据库故障或重复轮询，任务按既有恢复规则处理，不公开部分成功结果；失败不收费、成功仅按实际视频 URL 数执行一次幂等总额结算，且不泄露上游链接。 |
| GRSAI-VIDEO-06 | 给定另一把 API Key，查询视频任务详情或列表时不能看到不属于该 Key 的任务；视频用量记录的产出数量、请求时长、分辨率和金额与结果及实际结算一致。 |
| GRSAI-VIDEO-07 | 给定原有生图请求和灰度共库的新旧 worker，图片行为保持不变；旧 worker 不领取新视频任务，新 worker 可继续恢复旧图片任务。 |
| GRSAI-VIDEO-08 | 在 0% 候选槽位用最短视频实测时，能从提交追踪到本地 MP4 链接和一笔正确账单；健康检查、错误日志及旧图片回归通过后才允许切流。 |

## 已确认的结果下载来源

- 接受经过安全校验的公共 HTTPS 地址，不设置固定上游媒体域名白名单；每次重定向、DNS 解析和拨号均须防范内网访问及 DNS 重绑定。

## 待确认事项

- 上游返回多个视频 URL、最终费用高于预冻结金额，而用户可用余额不足以支付差额时，任务与结果应如何处理？在明确规则前不能承诺已成功交付或完整收费。

## 范围边界

- 本阶段不增加 `/v1/videos`、OpenAI 兼容视频接口、Composite 路由、用户取消
  或实时视频帧流。
- 不新增模型分类表、专属授权体系、充值流程或另一套视频价格配置。现有
  Grok 专用视频价格表不作为 GRS.AI 的价格来源。
- 对未来模型承诺请求参数透传；其输出结构和计费口径仍需符合本入口已支持
  的结果与按秒计费契约，超出契约时另行扩展。

## 工程改动清单（实施阶段）

以下为实现定位，不改变上方需求契约；具体文件可在实施计划中调整。

1. **解析与定价：** 扩展 `grsai_delivery.go`、`grsai_settlement.go` 和
   `grsai_task_service.go`，识别视频计费、精确选分辨率档位、校验时长、
   计算视频倍率并保留其余上游参数；图片路径继续使用原价规则。
2. **持久任务与灰度：** 扩展 GRS.AI 任务 schema、迁移和 repository，保存
   视频价格快照及媒体结果元数据；调整新旧 worker 的领取边界，并验证
   旧图片任务、冻结记录和共库回滚兼容。
3. **结果与存储：** 扩展 `grsai_native.go`、任务运行时和结果转存层以处理
   多个 MP4；视频下载采用有大小、超时、来源和内容类型约束的流式传输，复用
   现有 S3 链接策略，避免图片下载器的 32 MiB 内存路径。
4. **用量与界面：** 视频用量写入现有时长、分辨率和金额字段；分组开关的
   中文文案改为“允许图片/视频生成”，英文文案表达相同含义，不改数据库
   字段或 Grok 配价。
5. **验证与发布：** 覆盖解析、定价/冻结、真实数据库迁移、MP4 转存、
   三模式响应、权限、失败恢复、图片回归与新旧 worker 共库；离线测试
   使用假上游和假 S3，显式执行一次真实候选槽位测试后按灰度门发布。
