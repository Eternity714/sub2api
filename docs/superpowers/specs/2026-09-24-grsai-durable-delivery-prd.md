## 2. 背景与目标

现有同步返回不能让调用方在连接中断或服务重启后可靠找回结果。对目标模型的真实探测显示：
上游 JSON/Stream 可生成图片，但对应 `/result` 返回 404；上游 Async 任务可继续查询。
本阶段要求下游三种交付方式共享本地持久任务，在生成成功后将图片保存到本地 S3，
结果与终态入库以后才向调用方报告成功，成功最多结算一次。

## 3. 用户

- 使用 GRS.AI 原生接口的 API Key 调用方，需要同步结果、简化进度流或异步查询。
- 需要处理生成、转存和冻结异常的运营人员。
- 非目标：凭别人的任务 ID 或另一把 API Key 查询任务；图片链接本身不承担 API Key 鉴权。

## 4. 使用场景

1. JSON 调用等待结果，最终一次收到本地任务 ID 与本地图片链接。
2. Stream 调用先收到本地 ID，随后获得简化运行进度与最终结果。
3. Async 调用立即收到本地 ID，稍后查询。
4. 同步连接或进程中断后，调用方用原 API Key 列出历史任务，找回 ID 并查询结果。
5. 使用 presigned URL 时，链接过期后任务仍可出现在列表，但该链接无法续期或重新生成；使用公开 URL 时无签名过期时间。

## 5. 范围

**包含：** `replyType=json|stream|async`（默认 JSON）、本地持久 ID、上游统一 Async、
绑定上游 ID 后的后台恢复、结果本地存储、API Key 归属查询与列表、公开或 presigned 图片链接、
冻结和一次结算。

**不包含：** 上游 Stream/JSON 的 `/result` 恢复、逐帧进度或图片数据、Stream 连接
断线续传、用户取消、向下游暴露上游 ID/URL、图片专用删除策略、
过期 presigned 链接重新签发、Sub2API 图片下载代理接口、OpenAI 兼容层、Composite 分组。

## 6. 详细需求

### F1. 创建与三种交付

`POST /v1/api/generate` 仅接受合法字符串 `replyType`；通过鉴权、审核和准入后，
**先持久化本地任务 ID，再请求上游**，内部绑定上游 ID，任何下游响应都不得包含
上游 ID。JSON 同步等待完成，最终与本地图片结果一起返回本地 ID；不提前发送 ID。
Stream 开始先发送本地 ID，运行进度固定 `5/running`，成功且本地结果已就绪时
发送 `100/succeeded`；失败发送失败终态，不伪报 100。Async 返回 202 和本地 ID，
无需等待上游生成。Async 单用户最多允许 20 个等待任务、3 个运行中的后台任务；
达到上限时不能静默丢弃或超额接收任务。该限额须可配置。

### F2. 查询与历史列表

`GET /v1/api/result?id=<本地任务ID>` 查询状态和安全结果。新增分页任务列表，
只列出当前调用 API Key 创建的任务。列表帮助 JSON/Stream 连接中断后找回 ID。
列表和详情必须带创建任务的同一 API Key；归属不匹配时不能区分任务是否存在。
图片链接是独立的存储访问凭据，不要求再通过 Sub2API 图片接口鉴权；拿到公开 URL
或 presigned URL 的任何人都可以直接访问，直到公开 URL 不可用或 presigned URL 过期。
任务查询响应不含上游 ID、账号、价格或原始请求。

列表和详情显示本地图片链接的有效期信息：使用 presigned URL 时显示过期时间及
是否已过期；使用公开 URL 时显示期限不适用，不伪造 24 小时过期时间。该字段描述
链接访问期限，不声称 S3 对象到期；不检查对象是否存在。presigned URL 过期不等于
删除历史任务，任务元数据的保留独立管理。

### F3. 结果转存与图片链接

上游成功后须将全部图片下载到本地 S3，并把可供下游使用的结果与终态写入数据库，
然后才向 JSON/Stream 报告成功或让 Async 查询显示可交付成功。转存失败由后台重试，
超出恢复界限进入人工核查，不把上游图片链接给下游。S3 对象沿用现有管理和
清理策略，不添加 GRS.AI 专用删除规则。

本地结果链接直接由现有图片存储层生成：配置 `public_base_url` 时返回公开 URL；
未配置时返回 S3 presigned URL。不得新增 Sub2API 图片下载代理接口，也不要求
图片请求携带 API Key。拿到链接的任何人都可以直接下载；公开 URL 的可用性由
现有公开存储配置决定，presigned URL 的有效期沿用现有可配置图片链接时长，
默认 24 小时。presigned URL 过期后直接不可用，不刷新也不重新签发；两种情况
都不等于 S3 对象本身立即删除。

### F4. 后台恢复和计费

服务重启后，已绑定上游任务 ID 的本地任务可由后台继续调用上游 `/result`，
不得再次生成。上游提交结果未知且没有上游 ID 时，直接标记失败并释放冻结，
不自动重发；少数上游已接受请求的费用由平台承担。提交时冻结额度，仅可交付
成功按原有幂等规则结算一次；上游失败、违规或未知提交均不计费且解冻。

## 7. 非功能要求

- 任务查询和列表按创建时的用户 ID 与 API Key ID 限制；图片链接不经过 Sub2API
  鉴权。停用 API Key 影响任务查询，不影响已取得的公开 URL 或仍有效的 presigned URL。
- 多 worker、进程重启和重试不能重复生成、重复扣费或提前宣告成功。
- 敏感请求载荷只为提交/恢复安全保留，不进入日志、列表或公开错误。
- 分页受限；进行中和人工核查任务不能因图片链接过期而丢失。

## 8. API 交互

不新增用户 UI。客户端可直接使用图片 URL，包括普通 `<img src>`；结果链接可访问
不代表 S3 对象永不被既有 S3 策略清理。

## 9. 验收标准（AC-ID）

| AC-ID | Given / When / Then |
| --- | --- |
| GRSAI-DM-AC-01 | Given 三种合法模式或缺省，When 提交，Then 上游仅创建一个 Async 任务；非法交付字段返回 400。 |
| GRSAI-DM-AC-02 | Given 合法请求，When 上游 POST 发出，Then 已持久化当前用户/API Key 归属的本地 ID；公开响应不含上游 ID。 |
| GRSAI-DM-AC-03 | Given JSON 模式，When 上游成功，Then 图片存入本地 S3、结果和终态入库后，一次返回本地 ID 与最终结果。 |
| GRSAI-DM-AC-04 | Given Stream 模式，When 任务运行到完成，Then 首先发本地 ID，运行时仅发 `5/running`，成功且已持久化后发 `100/succeeded` 和结果；失败无假成功。 |
| GRSAI-DM-AC-05 | Given Async 模式，When 本地提交被接受，Then 立即 202 返回本地 ID，之后可查询。 |
| GRSAI-DM-AC-06 | Given 已绑定上游 ID，When 客户端断开或服务重启，Then worker 仅调用上游 `/result` 继续，不重新 POST。 |
| GRSAI-DM-AC-07 | Given 上游成功而下载/上传 S3 失败，When worker 恢复，Then 重试转存、暂不宣告成功；超界转人工核查且不返回上游 URL。 |
| GRSAI-DM-AC-08 | Given 提交结果未知且无上游 ID，When 判定无法安全恢复，Then 任务失败、解冻、不重发。 |
| GRSAI-DM-AC-09 | Given Key A 创建任务，When Key B、无 Key 或其他用户查询列表/详情，Then 不能看到该任务。 |
| GRSAI-DM-AC-10 | Given 结果已入库，When 返回图片链接，Then 配置 `public_base_url` 时使用公开 URL，否则使用 S3 presigned URL；不新增 Sub2API 图片下载接口。 |
| GRSAI-DM-AC-11 | Given presigned URL 使用可配置有效期（默认 24 小时），When 到期，Then 列表/详情仍显示任务、过期时间及已过期状态，不重新签发；公开 URL 的期限显示为不适用。 |
| GRSAI-DM-AC-12 | Given 重复轮询或多 worker 重试，When 任务终结，Then 成功最多计费一次，失败/违规/未知提交释放冻结。 |
| GRSAI-DM-AC-13 | Given live probe 未显式开启，When 离线测试/CI 执行，Then 无 GRS.AI 请求；显式验证覆盖上游 Async 提交和 `/result`。 |
| GRSAI-DM-AC-14 | Given 单用户 Async 有 20 个等待或 3 个运行中的后台任务，When 再提交/领取任务，Then 分别执行可配置限额，拒绝超额入队或暂缓领取；重启后计数仍正确。 |

## 10. 优先级

P0 为 AC-01..14 的完整端到端链路；不能以公开直链、丢失任务或重复结算替代上线。
OpenAI 兼容、Composite、取消和逐帧流留待后续阶段。

## 11. 度量

越权任务读取和重复计费成功次数为零；可观测未知提交、S3 转存重试、冻结滞留、
人工核查和重启后任务恢复完成情况。

## 12. 依赖

依赖上游 Async 提交及其 `/result` 查询、本地 S3 已配置、现有 API Key 鉴权和
一次结算能力。既有第一阶段同步 JSON 接口将发生响应契约变更，发布前需验证调用方。

## 13. 风险与开放项

无上游 ID 的不确定提交可能已发生上游费用，需内部对账，但不影响下游失败解冻。
上游长期无终态、图片转存反复失败和结算未完成需运营告警。技术字段、重试界限
与具体接口返回结构在技术设计和实施计划中落实，不写死在 PRD。

## 14. 里程碑

1. 书面评审 PRD 与技术设计，确认 AC-ID 追溯。
2. 按新设计替换旧实施计划，逐项实现与离线回归。
3. 完成真实上游、对象存储、鉴权、账务验收，再按仓库灰度流程发布。
