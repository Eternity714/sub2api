# API 密钥与分组

## 创建 API 密钥

API 密钥用于模型接口鉴权，与网页登录状态是两种不同凭证。浏览器已登录并不代表你的脚本或客户端已经配置密钥。

1. 登录后打开[API 密钥](https://www.gkotta.bid/keys)。
2. 点击创建入口，填写容易辨认的名称，例如开发环境或项目名称。
3. 选择分组。可以先在[可用渠道](https://www.gkotta.bid/available-channels)查看分组、支持模型及倍率。
4. 按需求设置额度上限、到期时间与 IP 限制，确认后创建。
5. 复制密钥，填入使用它的客户端或服务端环境变量。

为不同项目和设备使用不同密钥，有助于在[使用记录](https://www.gkotta.bid/usage)定位消耗，也便于单独停用某个凭证。

## 分组决定哪些模型可用

密钥绑定的分组会影响可用协议、模型、倍率和计费方式。账户拥有多个分组时，也要确认当前密钥选择的是目标分组。

- 使用 OpenAI 兼容工具时，选择支持所需 OpenAI 接口和模型的分组。
- 使用 Claude Code 或 Anthropic SDK 时，确认分组支持 Messages 协议及所选模型。
- 使用 Gemini 原生接口时，确认分组和模型支持该协议。
- 使用订阅分组时，确认[我的订阅](https://www.gkotta.bid/subscriptions)中存在该分组的有效订阅。

模型广场中的信息可用于选型；实际调用仍受当前密钥、分组权限和模型可用状态约束。

## 设置额度和到期时间

### 密钥额度

密钥额度上限是这个密钥允许消耗的金额上限，不会给账户充值，也不会扩大订阅额度。达到上限后，即使账户仍有余额，该密钥也可能无法继续生成内容。

在密钥页面查看已用额度和上限。若需要调整，编辑密钥并按实际预算修改；若页面提供重置已用额度操作，确认后再执行。重置计数不会退还已经发生的费用。

### 到期时间

到期时间可用于短期项目或临时工具。密钥过期后需要调整有效期或换用新密钥。注意本地显示时间和服务器计费周期可能使用不同的时间设置，以页面显示为准。

### IP 限制

配置白名单或黑名单前，先确认调用设备的公网出口 IP。服务器、公司网络与代理可能使用不同出口；切换网络后，原来的白名单可能不再匹配。

出现 `ACCESS_DENIED` 时，核对错误消息及密钥 IP 设置。不要为了排错把真实密钥发给他人。

## 在程序中保存密钥

macOS 或 Linux：

```bash
export GKOTTA_API_KEY="sk-YOUR_API_KEY"
```

Windows PowerShell：

```powershell
$env:GKOTTA_API_KEY = "sk-YOUR_API_KEY"
```

这些变量只影响当前终端及它启动的程序。打开新的终端、重启客户端或通过其他方式启动应用后，可能需要重新设置。持久化配置的方法由客户端决定，参见 [Claude Code](/claude-code) 和 [Codex](/codex)。

OpenAI 兼容请求的鉴权头为：

```http
Authorization: Bearer sk-YOUR_API_KEY
```

Anthropic 请求可使用 `x-api-key`，Gemini 原生请求推荐使用 `x-goog-api-key`。不要把密钥放进 OpenAI 或 Anthropic 请求的 URL 查询参数。

## 使用页面生成配置

密钥页面的使用入口可根据平台展示接入配置。优先复制你当前密钥对应的配置，并核对 Base URL 和模型。不要把另一个分组的配置直接套用到当前密钥。

手工配置教程中的 `YOUR_MODEL_ID` 需要替换成当前分组可用的模型 ID。模型显示名称与接口使用的 ID 可能不同，应使用页面或模型接口给出的标识。

## 停用、替换与泄露处理

如果密钥出现在公开文件、日志或截图中，立即在[API 密钥](https://www.gkotta.bid/keys)停用或删除该密钥，再创建新密钥。随后更新所有使用旧密钥的程序，重启应用并完成一次小请求验证。

停用操作会影响仍使用旧密钥的客户端。替换完成后，在[使用记录](https://www.gkotta.bid/usage)核对新密钥的调用情况和异常消耗。

需要区分账户余额、订阅额度与密钥配额时，阅读[计费与用量](/billing)。
