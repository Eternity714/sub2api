# 计费与用量

## 从哪里查看费用

Gkotta 的价格、分组倍率、套餐及购买方式以当前页面展示为准。模型、分组和活动设置可能调整，文档不固定承诺价格或优惠。

| 页面 | 可以查看或处理的内容 |
| --- | --- |
| [可用渠道](https://www.gkotta.bid/available-channels) | 分组、支持模型及适用倍率 |
| [模型广场](https://www.gkotta.bid/model-plaza) | 模型信息和选型参考 |
| [购买与充值](https://www.gkotta.bid/purchase) | 当前可用的余额充值、订阅套餐与支付方式 |
| [我的订阅](https://www.gkotta.bid/subscriptions) | 订阅分组、有效期、周期额度和用量 |
| [API 密钥](https://www.gkotta.bid/keys) | 单个密钥的分组、额度上限及已用额度 |
| [使用记录](https://www.gkotta.bid/usage) | 请求模型、Token 用量及费用明细 |

部分入口受站点功能设置影响。例如订阅未启用时，购买页可能只展示充值；充值方式是否可用也以页面实际显示为准。

## 区分三类额度

### 账户余额

余额用于按账户余额结算的请求。在[个人资料](https://www.gkotta.bid/profile)查看账户信息，需要充值时打开[购买与充值](https://www.gkotta.bid/purchase)。创建密钥或提高密钥上限不会增加账户余额。

### 分组订阅额度

订阅绑定指定分组，只有订阅有效且周期额度满足要求时才能按该订阅调用。订阅可能带有日、周或月限额，具体限额、重置时间及有效期见[我的订阅](https://www.gkotta.bid/subscriptions)。

账户有余额并不代表订阅分组一定可用；已购买某个分组的订阅也不意味着其他分组自动获得权限。

### 密钥额度

密钥额度是凭证层面的预算上限。在[API 密钥](https://www.gkotta.bid/keys)为单个项目设置限额，可以限制它允许消耗的金额。

达到密钥上限后，账户余额或订阅仍有剩余，该密钥也可能被拒绝。调整或重置密钥已用额度不会给账户充值，也不会退还已经发生的费用。

## Token 与费用明细

Token 是模型处理内容的计量单位，不等于字符或字数。不同语言、模型和分词方式会产生不同 Token 数，图片、工具说明和历史上下文也可能增加输入规模。

使用记录中可能出现以下用量：

- **输入 Token**：用户消息、系统提示、历史上下文以及请求中的其他内容。
- **输出 Token**：模型生成的回复。
- **缓存读取或缓存创建 Token**：支持缓存的模型可能单独记录这些类别。

输入、输出和缓存类别的单价可能不同。部分模型或能力采用其他计费方式；分组倍率、用户适用倍率和时段设置也可能影响结算。核对模型和分组展示，再以[使用记录](https://www.gkotta.bid/usage)中的实际费用判断消耗。

不要用一次请求的字数估算所有模型的费用，也不要仅用输入加输出 Token 总量比较不同模型的价格。

## 购买前确认

1. 在[可用渠道](https://www.gkotta.bid/available-channels)确认目标分组支持所需协议和模型。
2. 打开[购买与充值](https://www.gkotta.bid/purchase)，核对充值金额或套餐价格、有效期、周期限额及支付说明。
3. 订阅购买完成后，在[我的订阅](https://www.gkotta.bid/subscriptions)确认状态和对应分组。
4. 创建或编辑密钥，使它绑定需要使用的分组。
5. 用一条短请求验证，再查看[使用记录](https://www.gkotta.bid/usage)。

订单状态尚未确认时，先回到页面核对结果，避免连续重复支付。页面展示的支付金额与账户用于 API 结算的计费单位可能不同，应按订单说明核对。

## 控制项目成本

- 按项目或设备拆分密钥，在密钥层设置预算上限和到期时间。
- 选择满足任务需求的模型，先用短输入验证接入。
- 减少不必要的历史消息，长对话可以先做摘要。
- 按模型协议设置输出上限，避免一次生成不必要的长内容。
- 调整并发，避免多个任务同时重复处理相同输入。
- 定期按密钥、模型和时间范围筛选[使用记录](https://www.gkotta.bid/usage)。

模型请求已经发出后，客户端取消或超时不等于没有发生消耗。重试前先检查错误消息、已有输出和使用记录，避免重复生成。

## 额度相关错误

余额不足、密钥过期或订阅缺失可能返回 `403`；密钥配额用尽、订阅周期额度耗尽或调用频率限制可能返回 `429`。不同协议的错误字段会有所差异，需要结合响应消息判断。

按[常见问题](/troubleshooting)逐项核对；不要把所有 `429` 都当作余额不足，也不要把账户充值当作解决所有限额问题的方法。
