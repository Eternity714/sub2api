# 沉浸式翻译

沉浸式翻译可在网页中显示双语译文。配置它的 OpenAI 服务后，翻译请求可以通过 Gkotta 的 Chat Completions 接口处理。

## 安装和准备

从 [沉浸式翻译官网](https://immersivetranslate.com/)选择对应浏览器或移动端的官方安装入口。在 [Gkotta API 密钥](https://www.gkotta.bid/keys)创建翻译专用密钥，并确认[当前分组](https://www.gkotta.bid/available-channels)支持 OpenAI Chat Completions 和所选文本模型。

浏览器扩展会保存个人服务配置。请在自己的浏览器中填写密钥，为翻译用途设置合适的密钥额度；不要把真实密钥写到网页脚本或分享的配置文件里。

## 填写翻译服务

1. 打开扩展的**设置 → 翻译服务**，选择 **OpenAI**。
2. 选择使用自己的 API Key，填写 `sk-YOUR_API_KEY`。
3. 展开**更多设置/自定义设置**，配置以下字段。

| 字段 | 值 |
| --- | --- |
| 自定义 API 接口地址 | `https://www.gkotta.bid/v1/chat/completions` |
| 自定义模型 | `YOUR_MODEL_ID` |

4. 保存设置，使用页面提供的服务测试功能验证。
5. 将当前翻译服务切换成刚配置的 OpenAI 服务。

「自定义 API 接口地址」要求完整 Chat Completions 路径，不能只填 `https://www.gkotta.bid/v1`。模型 ID 使用分组允许的真实值，不能填控制台中的展示名称。

## 最小验证工作流

打开一个内容简短的英文网页，先选择一小段文字或手动触发本页翻译，确认译文显示在原文下方。再切回原文并重新触发一次，确认交互正常；到 [Gkotta 使用记录](https://www.gkotta.bid/usage)核对模型和消耗。

服务测试成功但整页失败时，先减少同时翻译的段落、关闭自动翻译和其他无关功能，再在同一个短段落复测。整页翻译可能拆成多次请求，调用数量和上下文大小会影响耗时及费用。

## 按阅读场景调整

需要技术文档翻译时，在官方支持的提示词设置中保留它的变量与格式规则，补充「保留代码块、命令和专有名词」等要求。不要删除默认模板的占位符，否则可能无法传入原文或正确分段。

网页双语、PDF、字幕、EPUB 和输入框翻译属于客户端不同的工作流，各自的版本、权限和格式支持以官方说明为准。先验证网页文本接口，再逐项使用其他工作流；PDF 上传成功不代表模型能直接解析原始 PDF 文件。

针对常用网站可以设置总是翻译或从不翻译规则。长文章先采用较低并发，逐步调整；发生限流时应减少并发，而不是反复点击整页重试。

## 常见问题

- **服务测试报 404**：检查完整地址是否以 `/v1/chat/completions` 结尾，路径中没有重复 `/v1`。
- **401/403**：检查密钥有效期、状态、额度和 IP 限制；浏览器或代理的出站地址可能与其他客户端不同。
- **429、长页反复失败**：降低翻译并发和单批段落数量，暂停自动翻译，按错误消息等待后重试。
- **测试成功但译文不显示**：确认当前选中 OpenAI 服务，检查网站规则、扩展权限及广告拦截器，刷新短网页复测。
- **格式错乱或代码被翻译**：保留默认提示词变量，检查网站翻译规则与代码区域处理方式。
- **费用增加较快**：避免重复翻译整页，限制专用密钥额度并查看使用记录；客户端缓存是否生效以当前版本为准。
